# Контракт: вход и восстановление пароля

Как в ЛК (`ag`, `sections/shared/Auth`): те же страницы и сценарий, на компонентах сайта.
Вёрстка: `app/components/sections/auth/*`, страницы `login.html` и `recovery.html` (имена — как в
ag). Витрина: `/dev/ui.html#story=auth`. Шапки и подвала нет.

Вид — как в ag: фон `#F5F8FA` (`bg-auth`), «← К порталу» слева сверху, логотип с подписью «Аптека
групп холдинг», белая карточка 440 (до 768 — без карточки), справа внизу крупное «AG», внизу полоса
со слоганом «Вместе – мы команда!» (`BG.Grey`). Поля и кнопка — компоненты сайта: Input с «глазом»,
кнопка General.

## Вход (`login`)

Логин, пароль с «глазом», ссылка «Восстановление пароля» → `recovery`, «Войти».

**Обычная POST-форма компонента входа Битрикса** (страница перезагружается, ошибку выводит
сервер). Модуль Form (`data-form-native`) только проверяет пустые поля перед отправкой (ошибка
под полем, фокус на первое) и показывает загрузку в кнопке. Имена полей и служебные скрытые поля —
как требует компонент (`fields.loginName`, `fields.passwordName`, `hidden [{ name, value }]`); в
демо — `USER_LOGIN`, `USER_PASSWORD`, `AUTH_FORM`, `TYPE`.

Ошибка входа с сервера: `error` — текст над кнопкой, оба поля красные; `login` — введённый логин.

## Восстановление пароля (`recovery`)

Без формы, как в ag: заголовок, текст «Для восстановления доступа к порталу обратитесь в
техподдержку по адресу» и почта (`card.link`, `mailto:`), кнопка «К форме входа» (`button`).
Тексты и почту правит админ.

## Поля AuthCard

`back { text, url }` («К порталу»), `logo`, `title`, `text`, `link { text, url }` (ссылка в конце
текста), `slogan`.

## Отличия от ag

В ag форма умеет отправку через JSON (`data-endpoint`) и проверку на лету (логин от 2 символов,
пароль от 4); здесь — обычная отправка формы Битрикса и проверка только при отправке (правило
проекта для коротких форм). Поля 46px с шрифтом 16 (iOS не увеличивает страницу), без масштабирования
по ширине экрана.
