# Контракт: вход, сброс пароля, код из SMS

Перенос старой вёрстки `my.ag-html-v2` (gulp: `login.html`, `login-error.html`,
`restore-password.html`, `restore-password-code.html`) на компоненты сайта. Вёрстка:
`app/components/sections/auth/*`, страницы — те же имена. Витрина: `/dev/ui.html#story=auth`.

Нового макета нет: вид по киту (Input · Extended `2405:788` — поле с «глазом» и «Не удается
войти?», кнопка General), фон и сценарии — из старой вёрстки. Шапки и подвала нет.

## Как работает

Все три формы — **обычные POST-формы компонентов Битрикса**, страница перезагружается, ошибку
выводит сервер. Модуль Form (`data-form-native`) только проверяет перед отправкой пустые поля и
формат телефона (ошибка под полем, фокус на первое) и показывает загрузку в кнопке. Имена полей
и служебные скрытые поля — как требует компонент (`hidden [{ name, value }]`, `fields.*Name`);
в демо — `USER_LOGIN`, `USER_PASSWORD`, `USER_PHONE_NUMBER`, `SMS_CODE`.

| Страница | Поля | Ошибка с сервера |
| --- | --- | --- |
| `login` | логин, пароль (с «глазом»), «Не удается войти?» → сброс | `error` — текст над кнопкой, оба поля красные (`login` — введённый логин) |
| `restore-password` | телефон (`type="tel"`), «Вернуться к форме входа» | `error` — под полем («Номер не найден») |
| `restore-password-code` | код (`one-time-code`, цифровая клавиатура), «Вернуться…», «Запросить код повторно» | `error` — под полем («Неверный код») |

«Запросить код повторно» — кнопка той же формы `name="resend" value="Y"` без проверки полей
(`formnovalidate`). После отправки кода бэк ставит `resend.wait` (секунды до повторной
отправки, обычно 60) — кнопка неактивна и показывает отсчёт; 0 — доступна сразу.

## Не нарисовано — наше

Маски номера нет (старая вёрстка брала Inputmask): формат проверяется при отправке. Логотип —
новый, как в шапке; иллюстрации фона — из старой вёрстки. Страницы закрыты от индексации
(`noindex`).
