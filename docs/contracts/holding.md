# Контракт: «Структура холдинга»

Черновик для согласования с бэкендом (Битрикс). Справочник смотрят двумя способами: по
юрлицам (этот документ) и по управленческой структуре (оргсхема, страницы дирекций и
подразделений — отдельно, по мере вёрстки). Карточка сотрудника — одна для обоих.

Страницы: `app/pages/holding-management.html` (по управлению — оргсхема), `holding.html` (юрлица), `holding-entity.html` (юрлицо без аптек — только
отделы), `holding-entity-network.html` и `holding-entity-pharmacies.html` (юрлицо с аптеками — по
отделам и по аптекам; на бэке это одна страница юрлица с параметром вида), `holding-employee.html`
(сотрудник). Блоки — `app/components/sections/holding/*`, общие — `components/Tabs`,
`components/SortMenu`, `components/Pagination`, `components/PhotoStrip` (лента фото, просмотр —
`PhotoViewer` без «Нравится»). Витрина: `/dev/ui.html#story=holding-hero` (и `holding-entities`,
`entity-info`, `brand-card`, `entity-staff`, `employee-row`, `employee-profile`, `entity-brief`,
`structure-place`, `employee-colleagues`, `photo-strip`).

## Страницы

Все страницы — `container page-inner page-inner--flush`: хлебные крошки, ниже содержимое. До 1024
`--flush` убирает общую белую подложку: каждый блок — белая полоса на всю ширину, между блоками —
серые 10 (так по мобильным макетам; блоки делают это сами).

1. **Юрлица** — `page-sections`: `HoldingHero`, `HoldingEntities`.
2. **Юрлицо** — `page-columns page-columns--aside-end`: `EntityInfo`, `BrandList` (боковая:
   `class: "page-columns__aside"`, внутри `BrandCard` по одной на бренд), `EntityStaff`.
   С 1024 бренды — колонка 350 справа на всю высоту, до 1024 — блок «Бренды N» последним на
   странице (переставляет CSS). Брендов нет — блока нет, место не остаётся.
3. **Сотрудник** — `page-columns page-columns--aside-start`: `EmployeeProfile`, боковая
   `page-columns__aside page-aside-cards page-aside-cards--tight` с `EntityBrief` и
   `StructurePlace`, `EmployeeColleagues`. С 1024 боковая — колонка 350 слева; до 1024
   «Место в структуре» встаёт над «Юридическим лицом» (CSS, порядок в разметке тот же).

Порядок в разметке — порядок на телефоне: первый блок основной колонки, боковая, остальные.

4. **По управлению** — `page-sections`: `HoldingHero` (текущий вид — «По управлению»), `OrgChart`.
5. **Подразделение** (дирекция, служба, отдел; `holding-directorate.html` — с юрлицами,
   `holding-unit.html` — без) — `page-columns page-columns--aside-start
   page-columns--aside-gap-20`: основная колонка `page-stack page-stack--gap-20` (`UnitHeader`,
   `UnitCards` — подразделения, `UnitCards` — юрлица, `UnitStaff`), боковая `page-columns__aside`
   с деревом структуры. С 1024 дерево — колонка 350 слева, до 1024 — панель на весь экран,
   открывает её поле «Структура: …» в `UnitHeader` (`tree`).

## Общие части

**`InfoList`** — строки «подпись: значение» (`dl`): `items[{ label, value, links[{ text, url }] }]`.
Пустая строка не выводится; несколько ссылок — через «; », номер телефона не переносится
посередине. `label` пишет бэк вместе с двоеточием («Телефон:»).

**`BrandChips`** — плашки брендов: `items[{ name, logo }]`, `label` (по умолчанию «Бренд» /
«Бренды» по числу), `emptyText` («Бренды уточняются» — пунктирная плашка, когда брендов нет).
Логотип — квадрат 28 (отдавать 56×56 для 2x).

**Вид страницы** («По управлению / По юрлицам», «По отделам / По аптекам») — `components/Tabs`
со ссылками: `links[{ text, url, current, count }]`, текущая — `aria-current="page"`. Это обычные
ссылки на страницы (GET), без JS. `count` — число после названия («По аптекам · 96»); у
«По отделам / По аптекам» оно видно только до 1024.

**`EmployeeRow`** — сотрудник в списке: `name`, `url` (карточка), `position`, `head` (метка
«Руководитель», текст — `headText`), `photo` (48, отдавать 96×96), `phone{ text, url }`,
`email{ text, url }`. Вся строка — ссылка, телефон и e-mail — свои ссылки поверх. Нет фото —
инициалы (две буквы ФИО). До 1024 — компактная строка (фото 44, без e-mail): данные те же.

### День рождения

В день рождения сотрудника выводится невидимый блок салюта (`components/Celebration`): при открытии
страницы конфетти вылетает от фото, снизу поднимаются шары. В остальные дни блока нет.

```html
<div class="celebration" hidden data-module="Celebration" data-path="components"
  data-celebration-key="ID сотрудника" data-celebration-origin=".employee-profile__photo"></div>
```

- `data-celebration-key` — постоянный ID сотрудника: салют сам показывается один раз в день у
  каждого посетителя.
- Выводить тем же сотрудникам и по той же дате, что и в блоке «День рождения» (дата сервера:
  скрипт её не проверяет).
- Если страница сотрудника кэшируется, признак «сегодня день рождения» считать вне кэша.
- Запасной вид — видимая метка «Сегодня день рождения» под ФИО (нажатие повторяет салют): вместо
  блока — кнопка `button.celebration.celebration--badge` из `Celebration.hbs` (`badge`).
- Кнопка «Салют (тест)» на демо-странице — только для показа, в шаблон не входит.

## По управлению

**`OrgChart`** — оргсхема: `title` («Управление холдингом»), `levels[]` сверху вниз, `footnote`
(«Данные о структуре и сотрудниках загружаются из 1С · обновлено …»).

- Уровень — `{ node }` (один узел по центру: Совет директоров, управляющая компания) или
  `{ nodes[] }` (ряд узлов под общей связью).
- Узел, у которого подчинённые показываются на этой же странице, — `panel` (id панели, например
  `org-corporate-center`) и `children{ caption, title, url (страница подразделения), text, head{
  name, role, photo (44 — отдавать 88×88) }, collapseText («Свернуть»), items[] (узлы) }`.
  `open: true` — панель раскрыта при загрузке (без JS раскрыть другую нельзя, поэтому раскрытую
  выбирает бэк). Раскрыта одна панель; раскрытие не запоминается.
- Остальные узлы с `url` — ссылки на страницы подразделений.
- До 1024 — дерево строк: под одиночным узлом «В подчинении · N» (`node.subordinates` — N: узлы
  следующего ряда + следующий одиночный узел; нет — без переключателя, подчинённые открыты)
  сворачивает всё, что ниже; под узлом с `panel` — «В подчинении · N» по числу `children.items`.
  Разметка — вложенные `.org-chart__sub` после каждого одиночного узла (кроме последнего уровня),
  закрываются в конце схемы; с 1024 на раскладку не влияют. `subordinatesText` — «В подчинении».

**`StructNode`** — узел (и подразделение на странице дирекции): `type` («Дирекция · Розница»),
`title`, `head{ name, role, photo }` (36 — отдавать 72×72; нет — без руководителя), `meta` («3
отдела · 18 сотрудников», «Руководитель не указан» — текстом), `url` (вся карточка — ссылка, стрелка
вправо) или `panel` + `open` (кнопка, стрелка вниз; раскрытый — синяя рамка). Без `url` и `panel`
— просто карточка.

## Подразделение

Одна страница для дирекции, службы и отдела: какие блоки есть — решают данные.

**`UnitHeader`** — `caption` («Дирекция · Управляющая компания»), `title` (H1), `tags[]` (строки:
«Направление: розница», «Бренды: …», «Юрлицо: …»), `copyText` («Скопировать ссылку» — копирует
адрес страницы), `parentLabel` («Подчиняется:»), `parents[{ text, url }]` (цепочка подчинения
сверху вниз), `head{ name, url, role, photo (72 — отдавать 144×144), phone{ text, url }, email{
text, url }, badge }`, `stats[{ value, label, short, mobileOnly }]` — две цифры: если в
подразделении есть юрлица — «юрлиц» и «сотрудников», иначе «отделов» и «сотрудников» (склонения —
бэк); у дирекции до 1024 — три: + «аптек» (`mobileOnly: true`), «сотрудников» — `short: "сотр."`.
Нет руководителя или цифр — без них.
`tree{ id (id дерева структуры), label («Структура:»), path («Корпоративный центр / Финансовая
дирекция») }` — поле до 1024, открывает дерево на весь экран; нет — без поля. До 1024 без
«Скопировать ссылку».

**`UnitCards`** — `title`, `kind` (`units` — подразделения, узлы `StructNode`; `entities` —
юрлица, `EntityCard`), `link{ text, url }` («Все юрлица холдинга»), `items[]`. Пусто — блока нет:
у дирекции без юрлиц блока «Юридические лица» нет.

**`UnitStaff`** — `title`, `sort` (`SortMenu`: «По подразделениям / По алфавиту»), `filters[{
text, url, count, current, icon }]` — вкладки «Все · 24» (`icon: profile`) и отделы (`icon:
folder`), ссылки (GET); `groups[{ title (подпись группы: «Руководство дирекции», «Отдел учета»),
employees[] (EmployeeRow) }]`, `pagination` (`Pagination`). Сортировка, отдел и страница —
параметры адреса, всё рисует бэк. До 1024 сортировка — поле на всю ширину под вкладками.

**Дерево структуры** — `sections/documents/DocumentsFolders` (тот же вид, что папки
документов): `id`, `title` («Структура»), `collapseAll` («Свернуть всё»), `countLabel` («,
сотрудников: » — для скринридера), `items[{ title,
url, count, current, expanded, children[] }]`. Бэк раскрывает ветку текущего подразделения
(`expanded`) и отмечает его (`current`).
