# Контракт: комментарии

Вёрстка: `sections/shared/Comments` (оболочка — Handlebars, дерево рисует `Comments.js`).
Блок общий: сейчас новости, дальше — любой материал (`entity` + `entityId`).
Витрина: `/dev/ui.html#story=comments` (сервер имитирует `app/pages/dev/mock-server.js`).
Демо-страница: `news-article.html#comments`.

Макет: Figma `4494:780` — компоненты (Comment/Item, Reaction, Reply box, Reaction picker,
Admin menu, Disabled notice) и «Состояния и поведение» 1–10. Основа API — прототип
`ag/docs/comments-prototype.html`, здесь он дополнен (отмечено «новое»).

## Оболочка (выводит бэк)

```hbs
{{> sections/shared/Comments/Comments props=(obj url="/ajax/comments.php" entity="news" entityId=123 count=28)}}
```

| props | Атрибут | Примечание |
| --- | --- | --- |
| `url` | `data-comments-url` | адрес API |
| `entity`, `entityId` | `data-entity`, `data-entity-id` | что комментируем |
| `limit` | `data-limit` | верхний уровень за раз, по умолчанию 8 |
| `count` | `[data-comments-count]` | число до загрузки (скрипт заменит на `total`) |
| `id` | `id` | якорь, по умолчанию `comments` (на него ведёт кнопка в новости) |
| `initial` | `script[data-comments-initial]` | необязательно: первая порция в формате ответа GET — дерево видно сразу, без запроса |

`initial` выводить через `json_encode(..., JSON_HEX_TAG | JSON_HEX_AMP | JSON_UNESCAPED_UNICODE)`:
`</script>` в тексте комментария иначе закроет тег. Без `initial` первая порция грузится, когда
блок в 600px от экрана (или сразу при переходе по `#comments`), до этого — скелетон.

Если комментарии отключены и их нет, блок можно не выводить вовсе (Figma 4519:2019).

## API

Все ответы — JSON. Ошибка — HTTP 4xx/5xx и `{ ok: false, message }`: `message` показывается у
поля или объявляется. POST — `Content-Type: application/json`, в теле `sessid`, в заголовке
`X-Bitrix-Csrf-Token` (оба — `bitrix_sessid()`). Права проверяет только бэк: фронт лишь
показывает то, что разрешили флаги.

### GET — порция

`?entity=news&entityId=123&parent=0&sort=new&limit=8&cursor=`

- `parent=0` — верхний уровень (по `limit`, по умолчанию 8); `parent=<id>` — ответы на
  комментарий (фронт просит по 20).
- `cursor` — из `nextCursor` прошлого ответа. **Курсор — по ключу (время+id последнего
  отданного), не смещение**: новый или удалённый комментарий иначе сдвинет порцию — будут
  пропуски и повторы. Фронт повторы отбрасывает по `id`, пропуски исправить не может.
- `sort=new` — новые сверху (так в макете). Другие порядки фронт пока не просит.

```json
{
  "currentUser": { "id": 1, "isAdmin": true },
  "commentsEnabled": true,
  "minLength": 10,
  "maxLength": 500,
  "total": 28,
  "nextCursor": "2025-03-28T10:00:00Z_1042",
  "items": [
    {
      "id": 1042,
      "parentId": 0,
      "author": { "id": 7, "name": "Наталья Дрозд", "role": "Менеджер", "avatar": "/upload/…/30x30.jpg", "url": "/company/personal/user/7/" },
      "text": "Текст комментария\nс переносом",
      "createdAt": "2025-03-28T10:00:00+03:00",
      "score": 9,
      "reactions": { "like": 9, "clap": 3, "heart": 5 },
      "myReactions": ["like"],
      "status": "approved",
      "edited": false,
      "deleted": false,
      "canEdit": true,
      "canDelete": true,
      "replyCount": 3,
      "replies": [ /* 2 последних ответа — в том же формате, с их replies */ ],
      "repliesCursor": "…"
    }
  ]
}
```

- `currentUser: null` — гость: без поля ввода, реакций и «Ответить» (только чтение).
- `commentsEnabled: false` — плашка «Комментарии к этому материалу отключены» вместо поля,
  нет «Ответить» и «Реакция», реакции видны, но не нажимаются; ⋯ у модератора остаётся.
- `total` — все комментарии материала вместе с ответами (число в заголовке).
- `text` — простой текст, переносы — `\n`. Фронт выводит его через `textContent`, HTML не
  нужен и не выполнится.
- `author.role`, `author.avatar`, `author.url` — необязательны (новое). Без аватара — серый круг.
- `score` = 👍 − 👎: «+N» зелёным, «−N» красным, 0 — не показывается.
- `status: "pending"` — пометка «на модерации» (новое: в макете нет, нужна, если бэк
  премодерирует; видит только автор).
- `edited` — пометка «изменено»; `deleted` — «Комментарий удалён администратором» (новое):
  так приходит удалённый комментарий, у которого остались ответы.
- `canEdit`/`canDelete` — ⋯ с «Редактировать»/«Удалить» (в макете — администратор портала).
- `replies` — 2 последних ответа (превью ветки), `replyCount` — сколько всего, `repliesCursor`
  (новое) — курсор для `parent=<id>`, чтобы дальше не отдать те же 2. Остаток показывается
  ссылкой «Показать ещё N ответов».
- Относительное время считает фронт от `createdAt` (ISO 8601 с зоной) и обновляет раз в
  минуту: «только что», «N мин назад», «N ч назад», «N дн назад», дальше — дата.

### POST `?action=create`

`{ entity, entityId, parentId, text, sessid }` → `{ ok: true, comment }` (формат — как в items).
Комментарий встаёт первым в ленте или ветке с подсветкой, `total` +1.

### POST `?action=react`

`{ commentId, type, sessid }`, `type` — `like | smile | clap | heart | party | hmm | dislike`
(👍 😀 👏 ❤️ 🎉 🫤 👎). Повторный — снимает. → `{ ok: true, reactions, myReactions, score }`.
Фронт меняет счётчики сразу и откатывает при ошибке.

### POST `?action=edit`

`{ commentId, text, sessid }` → `{ ok: true, comment }`. После — пометка «изменено».

### POST `?action=delete`

`{ commentId, sessid }` → `{ ok: true, mode: "placeholder" | "removed" }`. `placeholder` — у
комментария есть ответы, он остаётся заглушкой, ветка цела; `removed` — убран, `total` −1.
Без `mode` фронт решает сам по `replyCount`.

## Ограничения текста (проверяет и бэк)

- Минимум `minLength` (10) символов после чистки: подсказки «Минимум 10 символов»,
  «Ещё N символов», при отправке короче — «Нужно минимум 10 символов, чтобы отправить».
- Максимум `maxLength` (500, как в ag `comment-limits.js`) — `maxlength` у поля.
- Чистка перед отправкой: `\r\n` → `\n`, пробелы в концах строк, не больше одной пустой
  строки подряд, не больше 10 переносов (лишние — пробелы), пробелы по краям.
- Поле растёт с текстом до ~260px, дальше прокрутка; тянуть вручную нельзя. Ctrl/⌘+Enter —
  отправить, Esc — закрыть ответ или правку.

## Доступность

Кнопки реакций — `aria-pressed` и подпись с числом; панель реакций — стрелки влево/вправо;
меню ⋯ — стрелки вверх/вниз, Esc и клик вне закрывают и возвращают фокус; свернуть ветку —
`aria-expanded`/`aria-controls`, подсказки «Свернуть ответы» / «Развернуть ответы».
Итог отправки, правки, удаления и ошибки объявляются через `aria-live`.

## Открытые вопросы к бэку

1. Порция 8 и «новые сверху» — по макету; «горячие» сверху (из прототипа ag) пока не нужны?
2. Курсор по ключу вместо смещения, `repliesCursor` для ветки — ок?
3. Кто правит: только администратор портала (макет) или автор тоже (`canEdit`)?
4. Реакции — эмодзи из списка выше, свои нельзя. Храним в одной таблице реакций (прототип).
5. Гостям комментарии показываем (только чтение) или блок скрываем?
6. Премодерация нужна (`status: "pending"`)?
7. «Ответить Наталья Дрозд» — имя без склонения; если нужно «Ответить Наталье Дрозд», бэк
   отдаёт `author.nameDative`.
