# Контракт: выпадающий список (Select)

Общий компонент: `app/components/components/Select`. Витрина: `/dev/ui.html#story=select`
(там же имитация сервера — запросы видны в консоли). Макет: Figma, поле — `4704:1079`,
открытый список — `4706:1207`.

## Разметка от бэка

Обычный `<select>` внутри компонента: без JS работает системный список, форма отправляется
как обычно. JS заменяет его списком по макету и пишет выбор обратно в `<select>`, поэтому
имя поля, значение и отправка формы не зависят от того, какой список видит пользователь.

| Параметр | Что делает |
| --- | --- |
| `label`, `name`, `id` | подпись в поле, имя и id `<select>` |
| `options` | пункты `{ value, text, selected }` |
| `submit` | отправить форму сразу при выборе (фильтры) |
| `search` | строка поиска по пунктам — без запросов, для списков от ~10 пунктов |
| `url` | пункты с сервера (длинные справочники: сотрудники, аптеки). В `options` тогда только выбранный пункт (или «Не выбран») |
| `minChars` | с какой длины искать на сервере, по умолчанию 2 |
| `searchPlaceholder` | подсказка в строке поиска |

## Пункты с сервера (`url`)

Задача — не нагружать бэк:

- ничего не запрашивается, пока список не открыли;
- при открытии — одна порция без запроса поиска (`GET url`);
- поиск — через 300 мс после последнего ввода и только от `minChars` символов;
  короче — подсказка «Введите от 2 символов», запроса нет;
- новый запрос отменяет незавершённый (`AbortController`), устаревший ответ не выводится;
- ответы кешируются по тексту запроса (до 30), повторный набор — без запроса;
- следующая порция — при прокрутке к концу списка, по одному запросу за раз; если порция
  короче окна — следующая догружается сразу, пока окно не заполнится или не кончатся пункты.

Запрос: `GET <url>?q=<текст>&cursor=<из прошлого ответа>`, заголовки `Accept:
application/json` и `X-Bitrix-Csrf-Token` (если на странице есть ядро Битрикса), куки — свои.

Ответ:

```json
{ "items": [{ "value": "123", "text": "Волкова А.И. — аптека №125" }], "next": "20" }
```

- `items` — порция, **20–50 пунктов**; бэк сам ограничивает размер.
- `next` — курсор следующей порции (любая строка: смещение, id последнего) или `null`, если
  больше нет. Фронт его не разбирает, только передаёт обратно.
- Поиск по `q` — на бэке, без учёта регистра.
- Ошибка — любой статус кроме 2xx: в списке «Не удалось загрузить» и «Повторить», сообщение
  для скринридера.

Выбранный пункт, которого нет в `<select>`, добавляется в него — форма отправит его `value`.

## Доступность

Шаблон WAI-ARIA combobox + listbox: стрелки, PageUp/PageDown, Home/End (без поиска), Enter,
Escape, набор букв — переход к пункту (без поиска) или в строку поиска. Число найденных и
ошибки объявляются скринридеру.

## Не нарисовано в макете — наше

Строка поиска в окне, строки состояния («Загрузка…», «Ничего не найдено», ошибка).
Окно открывается вверх, если снизу мало места.
