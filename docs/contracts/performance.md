# Контракт: картинки, шрифты, иконки — скорость загрузки

Общие правила для всех блоков (поля и размеры каждого слота — в контрактах блоков). Всё ниже —
обычные атрибуты и файлы в шаблоне Битрикса, без скриптов.

Замер Lighthouse на демо (production-сборка), 2026-10-01: мобильный — все страницы 89–93
(разброс между прогонами ±3), десктоп — 97–100; сдвигов вёрстки (CLS) нет, SEO и best practices —
100, доступность 91–95 (контраст и размеры из макета, см. журнал вопросов).

## Картинки

- **Формат — WebP.** Включить конвертацию в настройках главного модуля (или отдавать WebP при
  ресайзе). Вёрстка принимает любой формат. Качество около 80.
- **Размер — под слот.** `CFile::ResizeImageGet` до размера слота из контракта блока; для экранов
  с плотностью 2x — вторая версия вдвое больше в `srcset` (`… 1x, … 2x` или с `w` и `sizes`, как
  в разметке блока). Оригиналы из админки на страницу не выводить.
- **`width` и `height`** — как в разметке (пропорция слота), сдвигов при загрузке не будет.
- **Первая картинка первого экрана** — `fetchpriority="high"`, без `loading="lazy"`: на главной это
  первый слайд баннеров. Остальные слайды и всё ниже первого экрана — `loading="lazy"`.
- Пока картинка грузится, под ней светлая плашка (цвет скелетона) — задано в CSS, бэку ничего
  не нужно.

## Шрифты

- В `<head>` — предзагрузка шрифта заголовков (он виден в шапке сразу):
  `<link rel="preload" href="…/fonts/RFRufo/RFRufo-Bold.woff2" as="font" type="font/woff2" crossorigin>`
  и то же для `RFRufo-Regular.woff2`.
- Пока шрифт грузится, текст виден системным (`font-display: swap`); для заголовков подобраны
  узкие системные шрифты, чтобы строки не перестраивались.
- Inter — три файла по наборам символов (кириллица 19 КБ, латиница 48 КБ, стрелки и знаки
  4,5 КБ) с `unicode-range`: браузер качает только нужные. Был один файл на 353 КБ.

## Иконки

- Спрайт — файл `assets/icons/sprite.svg` из сборки, кладётся в шаблон как есть. Иконка —
  `<svg class="icon …"><use href="<?=SITE_TEMPLATE_PATH?>/assets/icons/sprite.svg#icon-имя"></use></svg>`.
- На `<html>` — `data-icons="<?=SITE_TEMPLATE_PATH?>/assets/icons/sprite.svg"`: по нему иконки
  находит JS (подсказки поиска, календарь, комментарии).
- Предзагрузку спрайту не ставить: для `<use>` браузер её не использует и качает файл дважды.

## Прочее

- Фавикон: `<link rel="icon" href="/favicon.svg" type="image/svg+xml">` (пока — знак из логотипа).
- `robots.txt` и описание страниц (`<meta name="description">`) — из SEO-модуля Битрикса; портал
  открыт без входа, страницы индексируются (закрыты только ЛК и ERP).

## Сервер

- Сжатие gzip или brotli для HTML, CSS, JS, SVG (шрифты WOFF2 и картинки уже сжаты).
- Долгий кеш (`Cache-Control: max-age=31536000, immutable`) для файлов с хешем в имени
  (`assets/css`, `assets/js`, `assets/images`) и для шрифтов; для `sprite.svg` — с версией в
  адресе (`?v=` по дате файла) или короче.
- HTTP/2 — файлы модулей и шрифты грузятся параллельно.

## Браузеры

Цель — браузеры примерно за последние 3–4 года, без поддержки совсем старых:

| Браузер | Полностью | Работает, проще на вид |
| --- | --- | --- |
| Chrome, Edge, Яндекс, Opera, Samsung Internet; на Xiaomi — Mi Browser, на Huawei — Huawei Browser (все на Chromium) | 105+ (2022) | 99–104 |
| Safari на Mac и iPhone | 16+ (iOS 16 — iPhone 8 и новее) | 15.4–15.6 |
| Firefox | 121+ | 97–120 |

- Ниже Chrome 99, Safari 15.4, Firefox 97 стили не применятся (слои `@layer`) — такие браузеры
  не поддерживаем.
- «Проще на вид» — без анимаций появления, параллакса, подсветки выбранного раздела в поиске;
  всё читается и нажимается. Отступ под таб-баром и поиск на весь экран работают и там.
- Высоты окон и шторок: сначала `vh`, затем `dvh` — старые браузеры берут первое значение.
- Телефоны Huawei без сервисов Google: открывать сайт в Huawei Browser (обновляется через
  AppGallery); встроенные браузеры приложений там бывают старее — проверить на устройстве.

## Нет картинки или она не загрузилась

Бэку ничего делать не нужно. Под картинкой в блоке всегда лежит заготовка (светлый фон и значок,
у людей — силуэт или инициалы). Не загрузилась (битая ссылка, пустой `src`) — скрипт вёрстки
ставит `img.is-broken`, картинка прячется, видна заготовка. `onerror` на бэке не нужен.
Загрузилась — `img.is-loaded`: значок заготовки и инициалы аватара под ней убираются (иначе
просвечивают сквозь полупрозрачное фото: наведение на баннер, фото «Лидеров»).
Инициалы в аватаре — поле `initials` (две первые буквы имени); не передали — вёрстка берёт их
из `name`.

## Превью ссылок (Telegram, VK, мессенджеры)

В `<head>` каждой страницы — `og:type`, `og:url`, `og:title`, `og:description`, `og:image`
(+ `width`, `height`, `alt`), `og:site_name`, `og:locale` и те же для Twitter. В Битриксе — из
SEO-модуля / свойств страницы (`SetPageProperty`):

- адреса страницы и картинки — **полные** (`https://…`), иначе превью не покажется;
- картинка 1200×630; по умолчанию — `/og-default.jpg` из шаблона (временная, от дизайнера —
  финальная); у новости — её обложка, `og:type` = `article`;
- описание — 1–2 предложения, своё у каждой страницы.

Telegram кеширует превью: после смены картинки или текста — обновить через @WebpageBot.
